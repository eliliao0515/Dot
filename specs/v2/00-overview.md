# Dot v2 總藍圖：從 LINE 模擬器到數位素養課本

> 狀態：**已通過（Phase 0，2026-10-04）**　·　撰寫日期：2026-10-04
> 舊版規格 `specs/01`–`29` 保留作為歷史紀錄，不再修改。v2 之後的規格都放在 `specs/v2/`。

---

## 1. 一句話定位

**Dot 是一本給長輩的手機課本**：分成好幾個單元，每個單元有好幾關，
從「認得符號」、「會用手勢」一路練到「在 LINE 裡完成一件真實的事」。
裡面怎麼按都不會出事。

| | v1（現在） | v2（目標） |
|---|---|---|
| 教什麼 | LINE 的操作 | 數位素養：符號辨識、手勢、複合情境 |
| 首頁 | 仿 LINE 聊天列表 | 課本目錄（單元 → 關卡） |
| 外殼風格 | 自訂米色＋靛藍 | 極簡，參考 Apple HIG／SwiftUI 元件 |
| LINE 模擬器 | 就是整個 App | 其中一個單元「LINE 情境」的練習場，加上開發者專用的沙盒 |
| 形式 | 網頁（GitHub Pages）＋ Expo 原生 | **可安裝的網頁 App（PWA）**，原生版暫不推進 |

## 2. 決策紀錄

### 這次新確認的（2026-10-04，使用者本人）

| # | 決策 | 理由 |
|---|---|---|
| D1 | 產品目標從「學會 LINE」擴大為「數位素養」，分三個領域：符號辨識、手勢練習、複合情境演練 | 使用者決定 |
| D2 | 首頁改成課本目錄，有單元、有關卡 | 使用者決定 |
| D3 | **關卡不鎖**，只給推薦順序；首頁最上方永遠有「接著上次」 | 沿用原決策：被擋住的長輩會直接關掉 App |
| D4 | **每種手勢獨立一關**（點一下、長按、捲動、左右滑、拖曳、雙擊、雙指縮放） | 真手機上一定會遇到這些手勢，要專門教。原則「LINE 情境裡只用點一下和長按」**不變** |
| D5 | 舊的四堂 LINE 課保留內容和鷹架，搬進「LINE 情境」單元 | 已定稿的內容不重做 |
| D6 | 登入後，**只有開發者帳號**會看到一個「我的沙盒」關卡，可以自由操作 LINE 模擬器的所有功能，沒有題目也沒有提示 | 用來自己測試、對照真機驗收模擬器 |
| D7 | 外殼採極簡風格，參考 Apple HIG 和 SwiftUI 元件 | 使用者決定。長輩可用性的硬規定優先於 HIG，見 §6.2 |
| D8 | 網頁版要能安裝成 App（PWA） | 使用者決定 |

### 沿用不變（v1 定案，這次不重新討論）

- 第一原則：怎麼按都不會有後果。不給分數、不顯示紅色錯誤、不計時、做錯的路都放行
- 模擬畫面要跟真 LINE 幾乎一樣，不能為了好按而放大或簡化
- **唯一的成功指標是遷移**：在自己手機上、沒有提示的情況下能不能做到
- 鷹架要會退場；`realDevice` 可以跳過，但跳過的人要分開統計
- 不做遊戲化的競爭與稀缺機制（streak、分數、星等、百分比、排行榜、失敗音效）
- AI 界線：AI 可以產生情境內容，但介面和正確操作路徑都必須人工編寫
- 不用第三方的商標、logo 或貼圖素材，所有圖示都用 `View` 自己畫
- 強制 LINE 登入（2026-09-13 決策）
- 顏色分層：**靛藍是老師（外殼），綠色是要學的 App（模擬層）**。v2 的 HIG 外殼把靛藍當成強調色（tint），不會引入綠色

## 3. 課本架構

```
課本
├── [我的沙盒]               ← 只有開發者帳號看得到（D6）
├── 接著上次（大按鈕）
├── 單元一　認識符號
├── 單元二　手勢
├── 單元三　LINE 情境
└── （之後）單元四　防詐騙、單元五　調整手機（字級等）
```

### 單元一　認識符號（內容是草稿，Phase 3 開工前要逐條審過）

長輩最常卡住的，其實是「看不懂那個圖案是什麼意思」。這個單元每一關教一組意思相關的符號。

| 關卡 | 符號 |
|---|---|
| 往回走、回首頁 | 返回箭頭 `‹`、關閉 `✕`、首頁 |
| 找東西 | 放大鏡（搜尋） |
| 加東西、更多 | `＋`、`⋯`、`⋮` |
| 說話與看 | 麥克風、相機、電話、視訊 |
| 分享與儲存 | 分享、下載／儲存 |
| 設定與通知 | 齒輪、鈴鐺、紅點數字（未讀） |
| 不要亂按的 | 垃圾桶、警告三角 |

**防止學了用不出來**：每一關最後一步，一定是「在一個真實畫面裡找到這個符號」
（例如在 LINE 聊天畫面找到麥克風），不能只停在「看圖選意思」。
光是抽象地認得符號，回到真手機上不一定用得出來。

### 單元二　手勢（每種手勢一關，D4）

點一下 → 長按 → 上下捲動 → 左右滑 → 拖曳 → 雙擊 → 雙指縮放

- 每一關先在一個中性的練習畫面上練手感，最後一步再換到真實情境
  （例如：捲動 → 往上捲聊天紀錄；縮放 → 放大照片）
- 判定門檻（長按要壓幾毫秒、要滑多遠、雙擊間隔多久）**全部寫在腳本資料裡**，
  到實機上直接調。延續 v1 `minMs` 的做法
- 手抖友善：手指偏離目標一點也算數、移動速度不設下限、絕不因為「太慢」判失敗

### 單元三　LINE 情境（複合演練）

| 關卡 | 來源 |
|---|---|
| 看訊息、回訊息 | v1 搬過來 |
| 傳貼圖 | v1 搬過來 |
| 傳語音訊息 | v1 搬過來 |
| 把照片存起來 | v1 搬過來 |
| 接視訊電話 | 舊 spec 08，Phase 6 改寫到新引擎 |
| LINE 綜合練習 | v1 的「綜合練習」搬過來 |

### 我的沙盒（D6）

- 判斷方式：登入的 LINE userId 在開發者名單裡（實作見 §7.3）
- 內容：完整的 LINE 模擬器，包含聊天列表、分頁列、聊天室、貼圖、語音、照片、輸入框，
  全部都能按。**沒有目標、沒有紅圈、沒有「卡住了」、沒有完成判定**
- 外框標示「沙盒模式」，跟一般關卡區分開來

## 4. 每一關的學習結構

三個單元共用同一套鷹架，只是每一步的內容不同：

| 步驟 | 符號關 | 手勢關 | LINE 情境關 |
|---|---|---|---|
| 帶著做 `guided` | 指給你看：「這個是返回」 | 有動畫示範，紅圈標出位置 | 紅圈＋引導條（v1 現況） |
| 自己做 `solo` | 看圖選意思 | 在練習畫面自己做 | 沒有提示，有「卡住了，教我」 |
| 換情境 `transfer` | 在真實畫面裡找到它 | 在真實情境裡做 | 換人、換情境 |
| 到真手機 `realDevice` | 在自己手機上找到它 | 在自己手機上做一次 | 在自己手機上做一次 |

## 5. 畫面架構

```
未登入 ──► LoginGate（沿用）
已登入 ──► TabView
           ├── 課本（NavigationStack）
           │     ├── 課本首頁：大標題、接著上次、各單元（inset grouped list）
           │     └── 點一關 ──► 全螢幕練習（沿用 v1 的 stack 流程）
           │                    練習 → 到真手機 → 完成 → 回到課本
           └── 我：頭像、名字、登出（之後加字級設定）
```

- 底部分頁只有兩個：**課本**、**我**。v1 仿 LINE 的五分頁列移進模擬層，只在 LINE 情境和沙盒裡出現
- 還沒做好的關卡**照樣列出來、照樣能點**，點了跳出說明「這一關還在準備」（沿用 v1 的 MapNode 原則）
- 關卡狀態只有三種：沒做過、做過一部分（空心圈）、完成（打勾）。**不顯示百分比，也不顯示分數**

## 6. 設計語言

### 6.1 HIG／SwiftUI 元件對照（只用在外殼，模擬層不套用）

| SwiftUI | Dot 元件（`src/ui/hig/`） | 說明 |
|---|---|---|
| `NavigationStack` ＋ `.navigationTitle` large | `NavHeader` | 大標題，往下捲時不縮成小標題（避免畫面跳動） |
| `List` `.insetGrouped` | `GroupedList` | 淺灰底 `#F2F2F7`，白色圓角卡片 |
| `Section(header:footer:)` | `Section` | 單元標題、單元說明 |
| `NavigationLink` 列 | `ListRow` | 左邊圖示、標題、副標，右邊狀態和 `›` |
| `Button(.borderedProminent)` | `PrimaryButton` | 靛藍底白字 |
| `Button(.bordered)` | `SecondaryButton` | 淺靛藍底、靛藍字 |
| `TabView` | `TabBar` | 兩個分頁，圖示**一定**配文字 |
| `.sheet` | `Sheet` | 「還在準備」之類的說明，從下方滑出 |
| `Label` | `Label` | 圖示＋文字並排 |

### 6.2 長輩可用性優先於 HIG 的地方

| 項目 | HIG 預設 | Dot 規定 |
|---|---|---|
| 最小點擊區 | 44pt | 主要按鈕 **72px**，列表每一列 **64px** |
| 內文字級 | 17pt | 外殼內文 **≥ 20px**，並且吃系統字級縮放 |
| 只有圖示的按鈕 | 常見 | **禁止**，每個圖示都要配文字 |
| 列表的滑動操作、長按選單 | 常見 | **禁止**，所有功能都要看得到、點一下就能用 |
| 次要灰字對比 | 約 4.5:1 | 盡量做到 **7:1**（白內障） |
| 陰影 | 輕微陰影 | 沿用 v1：用描邊，不用陰影 |
| 毛玻璃 | 常見 | 不用，低對比的人看不清楚 |
| 錯誤顏色 | 紅色 | 外殼不出現紅色錯誤；紅色只用在引導紅圈 |

## 7. 技術方案

### 7.1 引擎 v2 資料模型（草圖，詳細內容在各階段 spec 定）

```ts
type Unit = { id: string; title: string; summary: string; levelIds: string[] };

type Level =
  | { id: string; kind: 'scenario'; title: string; subtitle: string; lessonId: string }   // v1 Lesson 原封不動
  | { id: string; kind: 'practice'; title: string; subtitle: string }                     // v1 綜合練習
  | { id: string; kind: 'symbol';   title: string; subtitle: string; script: SymbolScript }   // Phase 3
  | { id: string; kind: 'gesture';  title: string; subtitle: string; script: GestureScript }  // Phase 4
  | { id: string; kind: 'comingSoon'; title: string; subtitle: string };
```

- v1 的 `Lesson`、`StageScript`、`Target` **不改**，透過 `kind: 'scenario'` 掛進來
- 關卡 id 沿用 v1 的 lessonId，已經存下的進度不需要搬移

### 7.2 PWA（Phase 5）

- 手寫 `public/manifest.webmanifest` 和 `public/sw.js`，**不新增套件**（零額外套件的原則）
- 離線策略：App 本體和課程資料先存在快取裡，有網路時再到背景更新
- **跟強制登入有衝突**：LIFF 登入需要網路。做法是第一次一定要連網登入，之後離線時沿用上次快取的身分。Phase 5 開工前要再確認一次

### 7.3 開發者判定（Phase 2）

- 建置時用環境變數 `EXPO_PUBLIC_DEV_USER_HASHES` 放 **userId 的 SHA-256 雜湊**，不放原始 userId。
  這個值來自 GitHub Secret。打包後的程式碼是公開的，所以不能直接放原始 userId
- 執行時用 `crypto.subtle` 把目前登入者的 userId 算出雜湊再比對
- **這不是安全邊界**：沙盒裡沒有任何秘密，有心人改前端也只會看到一個模擬器。這一點會寫進程式碼註解

### 7.4 先拆開 ChatSim（Phase 2 的前置工作）

`ChatSim` 現在直接吃 `lesson`，裡面還有紅圈、引導條和「卡住了」按鈕，
**已經違反「sim 不知道課程存在」的分層規則**。沙盒需要一個沒有任何教學邏輯的 LINE 畫面，所以要先拆成兩層：

- `sim/LineChatScreen`：純 LINE 畫面，只吃 props。目標節點和成功判定都透過 callback 往外丟
- `shell/ScenarioRunner`：教學疊層，負責紅圈、引導條、卡住了、成功判定

## 8. 開發階段與審核關卡

**流程規則**：每個階段完成後，我會回報（做了什麼、怎麼驗證、哪裡要你看）→ 你審核 →
**你明確說「通過」，我才寫下一階段的詳細 spec 並開工**。
審核沒過就在同一個階段裡修。

| 階段 | 內容 | 你要審什麼 | 規模 |
|---|---|---|---|
| **P0** | 本文件＋ P1 詳細 spec | 方向、決策紀錄、課本架構、設計規則 | — |
| **P1** | 引擎 v2 骨架、HIG 元件庫、課本首頁、「我」分頁、舊四課和綜合練習搬家、更新 CLAUDE.md | 課本首頁好不好用；**舊課程的行為完全不變** | 中 |
| **P2** | 把 ChatSim 拆成兩層、開發者判定、我的沙盒 | 用你的帳號登入看到沙盒、別人的帳號看不到；四課行為不變 | 中大 |
| **P3** | 符號單元：引擎題型＋練習畫面＋自己畫的符號圖示＋內容 | **符號清單和每關內容先審一次再動工**；做完再審一次畫面 | 中 |
| **P4** | 手勢單元：七種手勢的偵測（PanResponder，不加套件）、門檻寫在資料裡、內容 | 手感；**一定要在入門紅米或三星 A 系列實機上試** | 大 |
| **P5** | PWA：manifest、service worker、安裝提示、離線 | 手機上能「加入主畫面」，開飛航模式還能上已快取的課 | 小中 |
| **P6** | 接視訊電話課（舊 spec 08 改寫成新引擎版） | 對照真機 LINE 的來電畫面 | 中 |
| 暫停 | 語音播放（舊 spec 01） | 要先有國語和台語的真人錄音 | — |

> **2026-10-04 調整**：使用者決定先做「打語音電話」（`specs/v2/P3-voice-call.md`），
> 原 P3 符號單元延為 P4（`specs/v2/P4-symbols.md`），之後各階段順延一號。

**為什麼這樣排**：
- P1 先搬家、不加新功能：每一步都可以驗證「舊東西沒壞」
- P2 的拆層是沙盒的前提，也能還清既有的分層違規；後面的符號和手勢單元也要用「在真實 LINE 畫面裡找到它」，同樣需要純 LINE 畫面
- PWA 排在 P5：它跟內容無關、隨時可以插隊。如果你想早點拿去據點試，可以提前

## 9. 範圍與代價（請看過）

CLAUDE.md 原本的優先順序是：**模擬器保真度 > 語音 > 三段鷹架 > 地圖 > 雙平台 > AI 生成**。v2 的影響：

1. **語音播放會再往後延**，而它原本是待辦第一名。不過它本來就卡在錄音，程式這邊做不了
2. 符號和手勢單元是**全新的、抽象的練習**，遷移效果比 LINE 情境更難保證。
   對策是每一關最後一定要接回真實畫面和 `realDevice`（見 §3）
3. 手勢偵測（P4）在網頁上，尤其是舊 Android 的瀏覽器上，**行為差異很大**，是整個計畫最大的技術風險
4. 原生 App（Expo iOS／Android）在 v2 期間**不會再驗證**，網頁版才是主要產品。原生版能不能跑起來不保證
