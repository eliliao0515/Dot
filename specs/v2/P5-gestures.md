## 1. 一題怎麼進行：猜猜看

```
任務卡（靛藍）：「想偷看女兒傳什麼，但不想讓她看到『已讀』」
        ↓
真的 LINE 畫面（綠色），長輩自己試
        ↓
 ┌─ 猜對了 → 「原來如此」卡片
 │              這個手勢叫什麼、在別的 App 通常也是這個意思
 │              例：「長按 ＝ 叫出更多選項。照片、訊息、App 圖示，壓著不放都會跳出選單」
 │
 └─ 還沒猜到 → 模擬器照真 LINE 的反應走（點了就真的打開聊天室）
                外殼給中性的一句話，然後可以再試
                提示一階一階給，長輩自己按「給我提示」才給：
                  第 1 次：方向（「試試看用壓的，壓著不要放」）
                  第 2 次：直接播示範動畫，手指在畫面上做一次
```

- **做錯的路照樣走得通，而且是學習的一部分**：點了聊天室就真的進去了，外殼說「這樣進去，女兒那邊會顯示已讀。按左上角回去，再想想別的辦法」
- 不顯示「第幾次才猜到」，**有沒有用提示點數都一樣**（不懲罰求助）
- 每題都在真實 LINE 畫面上，所以「每一關最後一定接回真實畫面」這條自然滿足
- 一關 = 一個手勢意思的幾題（見 §3），題目之間不用照順序

## 2. 「手勢的意思」— 這個單元真正要教的

長輩記不住每個 App 的每一個操作，但**手勢的意思在各個 App 之間大致相通**。每一關的「原來如此」卡片都回到這張表：

| 手勢 | 通常的意思 |
|---|---|
| 點一下 | 打開、選這個 |
| 長按 | 更多選項、先偷看一下 |
| 從左邊緣往右滑 | 回上一頁 |
| 往下拉 | 關掉（看照片時）、重新整理 |
| 雙擊 | 放大／縮回來 |
| 雙指張開、捏合 | 放大、縮小 |
| 壓著拖 | 把東西移到別的地方、調整大小或數值 |

## 3. 關卡清單（**請挑**）

### 3.1 你指定的

| 關卡 | 題目（任務卡草稿） | 要做的操作 | 要對照真機 |
|---|---|---|---|
| **長按：先偷看** | 「想看女兒傳什麼，但不想讓她看到已讀」 | 聊天列表長按那一列 → 跳出預覽 | ✔ 預覽長什麼樣子、iPhone 和 Android 一不一樣 |
| **長按：訊息的選單** | ① 「針對阿明那一句回話，讓大家知道你在回哪一句」→ 回覆<br>② 「把醫院的地址存起來，之後要找得到」→ 存到記事本<br>③ 「傳錯了，把這則訊息拿掉」→ 刪除／收回<br>④ 「把這張好笑的圖傳給老伴」→ 分享（轉傳） | 長按訊息 → 選單裡點對的那一項 | ✔ 選單截圖、選項名稱（「記事本」還是「Keep」）、選項順序 |
| **左邊緣往右滑** | 「看完了，回到聊天列表」（題目會說不要按左上角的返回鍵） | 從畫面左邊緣往右滑 | ✔ 真 LINE 聊天室能不能這樣回去（iPhone 可以；Android 是系統的返回手勢，見 §5） |
| **雙擊** | 「照片太小了，放大一點」 | 看照片時點兩下 | ✔ 真 LINE 看照片能不能點兩下放大 |
| **雙指縮放** | 「照片上那行小字寫什麼？放大來看」 | 看照片時兩指張開到 2 倍 | ✔ 同上 |
| **拖曳** | 待定，見 §3.3 | — | — |

**「刪除」和「收回」要特別處理**：真 LINE 裡「刪除」只刪掉自己這邊，對方還看得到；「收回」才是雙方都消失。
長輩在家族群組傳錯東西時，最怕的就是這件事。建議 ③ 拆成兩題，「原來如此」卡片講清楚差別。
**這兩個選項的真實名稱和行為要你對照真機確認。**

### 3.2 我另外找的、比較複雜的手勢（**請挑要哪幾個**）

全部要對照真機。我有印象但**不確定真 LINE 是不是這樣**的，都標「不確定」，不能憑我的印象做。

| 候選 | 題目草稿 | 手勢 | 為什麼值得教 | 真 LINE 是不是這樣 |
|---|---|---|---|---|
| **往下拉關掉照片** | 「看完照片了，回到聊天室」 | 看照片時往下拉 | 很多 App 的全螢幕照片、影片都這樣關，長輩常找不到 ✕ | 不確定 |
| **選取一部分文字複製** | 「訊息裡只有電話號碼要用，把號碼複製起來」 | 長按文字 → 拖曳選取範圍的兩端 → 點「複製」 | 長按 ＋ 拖曳的組合，最難也最實用（地址、電話、匯款帳號……也連到防詐） | 不確定 LINE 有沒有「選取文字」 |
| **按住錄音、滑開取消** | 「錄到一半講錯了，不要傳出去」 | 壓著錄音鍵，手指滑開再放 | 長輩怕「一放手就傳出去了」，學會取消就敢錄 | 不確定，要看現在的錄音方式 |
| **聊天列表往左滑** | 「把廣告帳號的聊天藏起來」 | 在聊天列表那一列往左滑，點「隱藏」 | 聊天列表被官方帳號洗版很常見 | 不確定，可能只有 iPhone |
| **長按貼圖先看大圖** | 「傳之前先看清楚這張貼圖在幹嘛」 | 貼圖面板裡長按（或點一下）貼圖 | 怕傳錯貼圖出糗 | 不確定是長按還是點一下 |
| **滑一下就回覆** | 「快速回覆這一句」 | 訊息往左（或往右）滑 | 比長按選單快 | 不確定 LINE 有沒有 |
| **相簿滑過去一次選好幾張** | 「一次傳三張孫子的照片」 | 選照片時，手指壓著滑過好幾張 | 一張一張點很累 | 不確定 LINE 的選照片畫面支援 |

**做不到、只能在「到真手機」教的**（系統層級，網頁沒辦法模擬，見 §5）：
從頂端往下拉出通知、從底部往上滑回主畫面、底部往上滑停住叫出最近用過的 App。
這些很重要，但在 App 裡模擬會直接觸發手機真正的動作。建議等單元五「調整手機」時，做成看影片＋到真手機做。

### 3.3 拖曳的情境（要你決定）

真 LINE 的日常操作裡很少拖曳。選項：
- **A**：如果 §3.2 選了「選取一部分文字複製」，拖曳就併進那一題（拖選取範圍的兩端），不另外做
- **B**：手機設定裡的字體大小滑桿（要新做設定畫面，兩個平台長得不一樣）
- C：影片進度條（模擬器要先能放影片）

建議 **A**，最實用而且不用另外做一個不是 LINE 的畫面。

## 4. 平台（要你決定）

上面很多操作在 iPhone 和 Android 的 LINE 不一樣（長按聊天室、左邊緣滑、往左滑隱藏）。模擬器目前照哪一個平台的截圖做，這一關就先照那個平台。建議**先照你手上那支手機的平台做**，另一個平台之後用 `screens.ios` 那種資料覆寫補上，不複製整份內容。

## 5. 手勢重疊：網頁最大的挑戰

### 5.1 會撞到什麼

| 我們要的手勢 | 會撞到的系統／瀏覽器手勢 | 在哪裡 |
|---|---|---|
| 左邊緣往右滑回上一頁 | 瀏覽器的「上一頁」 | iPhone Safari、LINE 內建瀏覽器 |
| 同上 | **系統的返回手勢**（左右兩邊都有），網頁攔不下來 | Android 全螢幕手勢 |
| 同上 | 沒有衝突，但也沒有任何預設行為 | iPhone 加到主畫面的 PWA |
| 長按（聊天室、訊息、文字） | 瀏覽器自己的選取文字、放大鏡、「拷貝／儲存圖片」選單、震動 | iPhone Safari、Android Chrome |
| 雙指縮放 | 整個網頁跟著放大（iPhone Safari 會忽略「禁止縮放」） | iPhone Safari |
| 往下拉關掉照片 | 下拉重新整理 | Android Chrome（`index.html` 已經關掉，要實機確認） |
| 從頂端／底部滑 | 通知欄、回主畫面、多工 | 所有手機，**完全攔不下來** → 不在 App 裡做 |

另外，現在的 `useHistoryBack` 只能管一層：LINE 模擬器推了一筆紀錄，如果練習裡再推一筆，
按一次「上一頁」兩個都會收到，**一次跳出兩層**（直接離開 LINE 模擬器）。要先改成一個統一管理的堆疊。

### 5.2 對策：「上一頁」不跟瀏覽器搶，而是把它當成答案

左邊緣往右滑在 Android 上本來就是系統的返回手勢，長輩回到真手機做的也是這個。所以：

1. 進入「左邊緣往右滑」這一題時，在瀏覽紀錄裡多推一筆**只屬於這一題的紀錄**
2. 收到「上一頁」事件（Android 系統返回、iPhone Safari 邊緣滑、Android 的返回鍵都會觸發）→ **算猜對**，紀錄退掉這一筆就好，不會離開 App
3. 在沒有系統返回手勢的環境（iPhone PWA）→ 我們自己偵測：手指從左邊 24px 以內開始、往右滑超過畫面寬度 1/3，就算猜對；畫面跟著手指往右滑開，跟真 iPhone 一樣
4. 兩條路同一時間只算一次

其他題的「上一頁」：照現在的做法，回到上一層（例如從聊天室回到列表），不算答錯。

### 5.3 其他對策

| 問題 | 對策 |
|---|---|
| 長按跳出瀏覽器自己的選單 | 練習區域關掉文字選取、圖片選單、右鍵選單（`user-select: none`、`-webkit-touch-callout: none`、攔 `contextmenu`）。**只在模擬層**，外殼的文字照樣可以選 |
| 兩指縮放整頁跟著放大 | 看照片畫面設 `touch-action: none`，攔下 Safari 的 `gesturestart`。外殼照樣能用系統縮放 |
| 舊 Android 瀏覽器偵測不到第二根手指 | 那一題顯示「這支手機的瀏覽器不支援，可以跳過」，不卡住 |
| LINE 內建瀏覽器的行為不一樣 | iPhone Safari、Android Chrome、LINE 內建瀏覽器三個都要試（跟鍵盤那條規定一樣） |

**P5a 第一件事就是做一個手勢測試頁**，在你的手機和紅米／三星 A 上把上面每一條都實際試一遍，確定哪些攔得住、哪些攔不住，再決定題目。如果某個手勢在某個環境攔不住，那一題在那個環境就改成「到真手機做」。

## 6. 技術做法（草圖）

### 6.1 引擎（`src/engine/types.ts`，只新增）

```ts
/** 手勢單元的一題。沒有 stage，不走鷹架。 */
type GestureChallenge = {
  id: string;
  /** 任務卡：講想做的事，不講手勢名稱。 */
  goal: string;
  /** 一開始的 LINE 畫面：哪個畫面、哪些訊息、誰傳的。 */
  scene: GestureScene;
  /** 什麼事件算猜對，例如 { type: 'chatPreview' }、{ type: 'messageMenu', pick: 'reply' }、{ type: 'back' }。 */
  pass: GesturePass;
  /** 做了別的事時，外殼說的中性話。key 是模擬層回報的事件。 */
  nudges: Partial<Record<string, string>>;
  /** 第一階提示（方向）。第二階固定是播示範動畫。 */
  hint: string;
  demo: GestureDemo;
  /** 猜對之後的「原來如此」。 */
  aha: { gesture: string; meaning: string };
};

type GestureLevelScript = {
  challenges: GestureChallenge[];
  thresholds: GestureThresholds;   // 長按毫秒、滑多遠、雙擊間隔……照舊寫在資料裡
  realDevice?: { headline: string; steps: string[] };   // 看 §1 的決定
};

// Level 加一種：(LevelBase & { kind: 'gesture'; script: GestureLevelScript })
```

## 8. Observable acceptance

1. `npx tsc --noEmit`、`npm run export` 通過
2. 「練習手勢」列出選定的關卡，每一關都能直接點進去
3. 每一題：做錯的路照樣走得通，外殼只給中性的話；按「給我提示」先給方向、再播示範；有沒有用提示點數一樣

7. iPhone Safari、Android Chrome、LINE 內建瀏覽器都試過；**入門紅米或三星 A 系列實機上試過手感**
