本頁說明「長輩手機練習」（下稱「本服務」，網頁版名稱 Dot）在使用者使用過程中，個人資料如何被蒐集、利用與保護。本服務由〔開發者姓名或慣用名稱，請自行填入〕（下稱「開發者」）獨立開發與維運，為個人非商業性質之專案，並非公司或其他法人組織。

一、服務性質

本服務是一套教導 65 歲以上使用者操作智慧型手機通訊軟體介面的沙盒模擬練習工具。畫面中出現的所有聯絡人、對話內容與情境，均為預先編寫的教學情境，並非真實人物或真實訊息往來——使用本服務不會、也無法傳送任何訊息給真實的人。

二、本版本目前實際蒐集之個人資料

本節描述本服務目前部署版本的實際行為，皆已對照原始碼確認：

  • 本服務不需要註冊或登入即可使用全部練習內容。
  • 本服務目前未蒐集任何足以直接或間接識別使用者身分的個人資料。
  • 使用過程中的練習進度、模擬對話狀態，僅存在於使用者當下瀏覽器分頁的暫存記憶體中；關閉分頁或重新整理頁面即會清除，開發者沒有、也無法將這些內容傳輸或儲存到任何伺服器或資料庫——因為本服務目前並未架設任何後端伺服器。
  • 本服務未使用任何網站流量分析、行為追蹤或廣告工具（例如 Google Analytics、Meta Pixel 等）。
  • 本服務未使用 Cookie 或任何形式的本機追蹤技術儲存個人資料。

三、規劃中、尚未啟用的功能

規劃中・尚未上線

為了讓使用者的學習進度能夠保存並在下次開啟時接續練習，本服務規劃於後續版本加入「使用 LINE 帳號登入」功能（透過 LINE 官方提供的 LIFF 技術）。以下說明僅描述規劃中的設計，在該功能實際隨對應版本上線前，本服務並不會、也沒有能力進行下列任何一項資料蒐集行為。此功能一旦啟用，開發者會同步更新本頁最上方之「最後更新日期」，並於服務內以顯著方式重新告知使用者。

規劃蒐集之資料類別：LINE 使用者識別碼（User ID）、顯示名稱（Display Name）、大頭貼圖片網址（Picture URL）——這三項是 LINE LIFF 於 profile 權限範圍下可提供的欄位。

明確排除、不會蒐集：電子郵件信箱、電話號碼、LINE 好友清單、LINE 聊天訊息內容、位置資訊。本服務規劃申請的 LIFF 權限範圍僅止於 profile，不會申請 email 權限。

規劃用途：前述識別資料僅用於辨認「這是同一位使用者」，以便將學習進度（例如已完成哪些練習、進行到第幾階段）保存在使用者自己的裝置本機儲存空間（例如瀏覽器的 LocalStorage）。這些進度資料規劃為只存在使用者自己的裝置上，不會上傳、傳輸至開發者或任何第三方持有的伺服器——因為本服務規劃階段並未包含架設任何後端伺服器或資料庫。

Privacy Policy

Last updated: 2026-09-12 (update this date whenever this page is revised)

This page explains how "Dot" (Traditional Chinese name: 長輩手機練習, a phone-skills sandbox simulator for elderly learners; referred to below as "the Service") handles personal data. The Service is developed and operated by 〔developer's name or handle, please fill in〕 ("the developer"), as an individual, non-commercial project — not a company or other corporate entity.

1. Nature of the Service

The Service is a sandbox simulator that teaches users aged 65 and above how to operate the interface of a mobile messaging app. Every contact, conversation, and scenario shown is scripted teaching content — none of it is a real person or a real message; using the Service never sends any message to a real human being.

2. Data Currently Collected by the Deployed Version

This section describes the actual behavior of the currently deployed version, verified directly against the source code:

  • The Service requires no account and no sign-in to use any of its content.
  • The Service currently collects no personal data capable of directly or indirectly identifying a user.
  • Lesson progress and simulated conversation state exist only in the current browser tab's in-memory session; closing or reloading the tab clears them. The developer neither transmits nor stores this content on any server or database, because the Service currently has no backend server at all.
  • The Service uses no analytics, tracking, or advertising tools of any kind (e.g. Google Analytics, Meta Pixel).
  • The Service uses no cookies or any local tracking mechanism to store personal data.

3. Planned, Not-Yet-Active Features

Planned · Not Live Yet

To let a learner's progress persist between visits, the Service plans to add "Sign in with LINE" (via LINE's official LIFF technology) in a future version. Everything below describes that planned design only — until the corresponding version actually ships, the Service does not and cannot perform any of the data collection described here. Once activated, the developer will update the "Last updated" date at the top of this page and re-notify users prominently within the Service.

Planned data categories: LINE User ID, Display Name, and Picture URL — the three fields available under LIFF's profile scope.

Explicitly excluded, never collected: email address, phone number, LINE friend list, LINE chat message content, location data. The Service plans to request only the profile LIFF scope, never email.

Planned purpose: the identifying data above would be used solely to recognize "this is the same user" so that lesson progress (which lessons are complete, which stage a lesson is on) can be saved to the user's own device (e.g. browser LocalStorage). This progress data is planned to remain on the user's own device only — never uploaded to any server held by the developer or any third party — because the plan does not include standing up any backend server or database.

5. Period, Region, Recipients, and Manner of Use

  • Period: the current version collects nothing, so no retention period applies. Once the planned feature ships, identifying and progress data live only on the user's own device; retention is entirely up to the user (clearing browser data, uninstalling, or using an in-app clear function removes it) — the developer sets no separate retention period because the developer never holds the data.

  • Manner: currently none; the planned feature stores data on the user's own device, not on any server held by the developer.

6. Data Subject Rights

Under Taiwan's Personal Data Protection Act, Article 3, users may exercise the following rights over their personal data: to inquire or request access, to request a copy, to request supplementation or correction, to request cessation of collection, processing, or use, and to request deletion.

Since the current version collects no personal data, these rights currently have nothing to apply to. Once the planned sign-in feature ships, because identifying and progress data live only on the user's own device, exercising the "deletion" right means: clearing browser storage, or using the Service's built-in clear/sign-out function (if not yet provided, clearing browser data or uninstalling achieves the same effect). For any other request or question, please contact the developer using the details below.

9. Minors and Users Under Guardianship

The Service targets users aged 65 and above, some of whom may use it with the assistance of family members, caregivers, or volunteers due to cognitive, visual, or mobility limitations. Where a third party operates the Service on a user's behalf — including completing the planned sign-in process — that is treated as the user's own action; the developer cannot and does not verify the actual operator's identity.

The Service does not specifically target users under 18. If a guardian discovers a minor has used the Service and provided personal data without consent, please notify the developer using the contact details below, and we will assist per the rights described in Section 6.

10. Policy Revisions

The developer reserves the right to revise this policy at any time; revisions will update the "Last updated" date at the top of this page.

If the Service later adds server-side sync features (e.g. a planned caregiver dashboard for viewing a learner's progress), that constitutes a material change in the purpose and manner of data use. The developer will update this policy before such a feature goes live and re-notify users prominently, and may need to obtain renewed consent at that time.
